# Accessibility

## Principle
Accessibility is part of interaction design, not a final polish checklist.

## Practical checks for this game
- Important information is not carried by sound alone.
- Important information is not carried by colour alone.
- Text remains readable at small browser/mobile sizes.
- Contrast survives bright outdoor viewing and visual clutter.
- Controls have keyboard and touch equivalents where applicable.
- Camera/FOV/motion settings can reduce discomfort without breaking play.
- Time pressure does not make basic onboarding impossible.
- Hazards have readable object/shape/motion cues.
- Critical UI can be understood with game audio muted.

## Contexts to test
Real players may be on:
- small screens;
- muted audio;
- noisy environments;
- bright outdoor light/glare;
- lower-performance devices.

## Project rule
When a gameplay cue matters enough to cause failure, ask whether the player can perceive it through more than one useful channel without flooding the screen.
