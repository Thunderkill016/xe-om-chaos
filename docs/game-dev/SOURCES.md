# Sources & Research Policy

## SOURCE POLICY
When learning game development:

1. Prefer primary or professional sources:
   - academic papers;
   - established textbooks;
   - official engine/platform documentation;
   - GDC talks from practitioners;
   - postmortems from shipped games.
2. Distinguish clearly between FACT, FRAMEWORK, CASE STUDY, AUTHOR OPINION, and PROJECT HYPOTHESIS.
3. Never convert a case study into a universal law.
4. Never invent numerical design rules unless a source actually establishes them.
5. When sources disagree, preserve the disagreement.
6. Extract only what is relevant to the current game.
7. Research must eventually produce an experiment in the playable build.
8. Stop researching once there is enough evidence for the next development decision.
9. The current playable game and real player behaviour remain final validation.
10. Cite the original source in internal research notes.

## Research-note format
`SOURCE → PRINCIPLE → CONTEXT → LIMITATION → RELEVANCE → HYPOTHESIS → EXPERIMENT → RESULT → DECISION`

## Rule for deeper research
Do not open another topic because it sounds useful. Open it because an observed build problem requires it, then turn the result into the smallest testable experiment.
